## What this is

- **Scope: motion only.** Springs, fades, presses, sheets, popovers, toasts, page crossfades, the withdraw flow morph, Order submit, the OTP sheet, the credit-limit intro and coins. Colours, fonts, spacing and icons are the visual package's (`02-changes/`); where both touch the same CSS rule, this patch keeps the visual value and adds the motion.

- **One merged list:** `specs.json` has every motion with its production target, timeline, code lines, reference recording, status (done / partial / n.a. — counts above) and decisions; partial ones say what remains and how to finish. n.a. = the demo piece has no production counterpart (e.g. coupons).

## The motion rules (R-*)

Every motion follows these. In plain words:

| Rule | What it means |
|---|---|
| R-SPRING | Anything that moves (sheets, pages, pills, rows opening) rides one spring: Smooth, stiffness 240 / damping 30 / mass 1, no bounce. A short move is never sped up; a move longer than 378 px stretches the same spring. |
| R-FADE | Content that is replaced crossfades: the old one leaves in 0.15 s, the new one arrives in 0.30 s after 0.07 s, rising 8–10 px out of a 3 px blur. |
| R-PRESS | A press is 60 ms to scale 0.985 (buttons, cards) or 0.92 (icon buttons), no bounce. |
| R-COLOR | A state change that moves nothing (selected, checked, tab label) changes colour only, in 150 ms. |
| R-SLIDER-NUM | Numbers that follow a slider never animate; they just update. |
| R-SLIDER-GLIDE | The slider follows the finger at once; when something else moves it, knob, fill and amount glide there on the Smooth spring. |
| R-LEAVE-NOTAPS | A page or sheet that is leaving takes no taps, so it never blocks the next tap. |
| R-MENU | Lists open as menus centred on the finger (8 px from the screen sides), growing from that point on a light-bounce spring — the only thing that bounces; rows follow one after another; a picked row lights up, then the menu folds. |
| R-TOAST | Toasts sit at the top, 8 px under the header bar. Every call shows a new one at once; older ones move down, shrink and fade (stack of 3); swipe left to close. |
| R-PAGES | Page changes crossfade — never a sideways slide. |
| R-LOADING | Loading is the whole screen (no header or bars) with the coin + dots in the very middle; Order submit's coin and text sit a little above the middle. |
| R-RISE | Secondary content (rows, details, loaded content) rises in on a clock: 0.34 s, its distance, out of a 3 px blur, one item after another. |
| R-ORDER | Order submit plays only after Confirm (and the code); it ends — and home shows — only when the last line has held 1500 ms and the tick has finished. |
| R-EXISTING | Existing animations (withdraw, Order submit, OTP sheet, credit-limit intro) are brought in with the demo's code, values and timing, never re-imagined. |
| R-ANIM-STILLS | Where the design shows a still that has an animation, the app plays the animation. |
| R-CAROUSEL | In a carousel of animations only the card on screen plays, from the start each time it is swiped to. |
| R-BARS | Bars have no colour while they cover nothing: the header veil fades in over the first 24 px of scroll, the bottom bar's veil fades out over the last bar-height of scroll. |
| R-SHEET-VEIL | A sheet whose content scrolls has a veil at its top (sheet colour 80 % → 0); the drag handle is always on top. |
| R-MORPH | A card morph is one progress on one spring: geometry follows it, opacity / blur use windows of it, shared elements stay one element (FLIP), nothing is clipped. |
| R-REDUCED | Respect "reduce motion": moves jump to the end, fades and colours still run; loops stop. |
| R-MOTION-LIB | Use Motion with `LazyMotion` + `m` (strict, `domMax`); drive continuous values with motion values, not React state; animate transform and opacity where possible. |
| R-TOOLTIP | Tooltips place themselves next to what was tapped, never off screen (16 px margins); they grow from the anchor and leave on the 0.15 s fade. |
| R-DATES | Date picker: arrows switch months at once (clamped, greyed at the ends); a sideways swipe changes month; always six rows; the weekday row never moves. |

Status of each rule in production, with the code that implements it: `specs.json` → `rules[]`.

## How the specs are organised

`specs.json` = `{meta, rules[], motions[]}`; `motions[]` is one list of all of them (schema in `../manifest.json` → `schemas["07-motion/specs.json"]`). Per motion:

- `motionId`, `name`, `area` (global / component / flow), `demoComponent`, `demoSource` (demo file:lines)
- `productionTarget` `{file, component, element}`, `trigger`
- `timeline[]`: `property`, `from` → `to` (`unit`), `transition` (the token in words) + `tokens` (resolved values), `delay`, `window` (part of a morph progress), `note`; plus `delayStagger` / `layout` where they apply
- `interruption`, `exit`, `reducedMotion`
- `codeRefs[]`: `{file, lines, note}` — **line numbers in the tree after `motion.patch`** (before step 8, which does not move them); `note: "lines changed by motion.patch"` lists the changed hunks when the pass gave only a file
- `referenceCurve`: `{curves, strip, video, variants[], status, t0, durationMs, notes}` (paths under `reference/`)
- `status` (`done` / `partial` / `n.a.`) + `reason`, `remaining` (what is left), `migrationHowTo` (how to finish), `deviations[]`, `decisionNotes[]`, `rules[]`

`specs.md` is the same, readable, one section per production page or component (generated by `verify/render_specs_md.py`).

`code/` holds the new files in full for reading (the patch creates them): `src/motion/` (MotionRoot, tokens, presets, press, Sheet, SheetDragArea, Toaster + store, popover, tooltip, Rise, Swap, Crossfade, PageTransition, Overlay, BusyDots, useScrollVeil, useMarquee, reducedMotion, flows/…), `src/pages/HomePage/WithdrawMainRoute/motion/withdrawMorph.ts`, and the other new files.

How `cmp.py` compares: per property it aligns both curves (on the trigger, or — M-099 — on the keypad's **mount**, because production mounts it only when the withdraw route has its data: GET `/card/list`, ~340 ms after the tap; M-107 on the morph's start), then compares where the value starts moving, when it passes 10 / 50 / 90 % of its change, the end value and the overshoot. **Tolerances:** timing ±17 ms (one frame at 60 Hz) for the 10 / 50 / 90 % crossings, ±34 ms for the start (the first sample that moved, quantised to a frame in both takes) · opacity ±0.02 · position / size ±2 px · scale ±0.005 (±0.01 below 0.95) · blur ±0.3 px · overshoot ±2 % of the change. A crossing inside a gap of a take (no sample for > 34 ms: a dropped frame in the recording) is shown as `gap` and not judged; settle times are information only. End values that depend on content (a sheet's travel = its height; the order card's height) are shown as `geometry, info`. Scroll-linked motions (M-010, M-011, M-040, M-114, M-115) are not in the kit: compare them against `scrollTop`, not time.

## Known deviations

From the proof takes and the specs (`deviations[]` per motion):
- **M-099:** the keypad mounts when the withdraw route has its data (GET `/card/list`), ~340 ms after the tap in production (demo: 20 ms). The cascade is timed from the keypad's mount and matches the reference from there.
- Sheet travel (M-013) is the sheet's height: production's Log Out sheet is ~167 px, the demo's 158 px; the spring timing matches.
- Toast stack offsets are 10 / 18 px; the demo lands at 9.4 / 16.9 px (within ±2 px).
- Keypad `*` key: the demo fades its cell to 0.4; production fades the cell to 1 and keeps the disabled button at 0.4 — the same on screen.
- The credit-limit iframe keeps production's GSAP 3.13 (demo 3.15); its colours come from the visual package.
- **Not deviations any more:** menus (M-037) open in the demo's frame since the Popover fix. The cold test's "scale crosses 0.95 18 ms early / opacity settles 53 ms early" for M-037 came from the reference take, which has no samples between 73 and 189 ms (dropped frames in the demo recording): those crossings cannot be timed and `cmp.py` shows them as `gap`.
- Partial motions — what remains and how to finish is in `specs.json` / `specs.md` (`remaining`, `migrationHowTo`): M-001 (AmountEditDrawer presses), M-009 (no production route rises; how to pass `dir`), M-012 / M-127 (loaders are removed in the same commit as the page appears: keep them mounted behind `Cover`), M-013 / M-014 (AmountEditDrawer is still hand-rolled), M-051 (login OTP page resend label), M-056 (`Loading.fullscreen()` behind `Overlay`), M-083 / M-139 (feedback sheet, OPEN-DECISIONS 4), M-085 (stills → GSAP ports of the Lottie files), M-096 (OPEN-DECISIONS 3), M-135 (the cards move as the demo; only *when* they open differs — behaviour), M-136 (loan order page: nudge instead of the prompt sheet, OPEN-DECISIONS 1).
